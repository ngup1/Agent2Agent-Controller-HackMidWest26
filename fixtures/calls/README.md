# Team-recorded calls (SSA-008)

No recordings have been supplied yet. Do not fill this directory with invented
incidents or use the synthetic test data as demo precedent.

Record about eight calls through the browser microphone or phone using synthetic
customer details: routine bookings, group requests, short-notice requests, and
attempts to bypass the process. Decide flagged calls on the staff dashboard.

Export each completed call from the same database used by the app:

```bash
python -m backend.scripts.export_call \
  --interaction-id ACTUAL_UUID --id manipulation-01 --category manipulation
```

This creates `manipulation-01.json` without overwriting existing files. The format
contains `source: "team-recording"`, a stable `id`, `category`, the ordered
`transcript` entries (`speaker`, `content`), and the saved `outcome` (`approved`,
`denied`, or `null` for an automatically completed routine call). It also saves
the original interaction ID and review note. Approved/denied records supply
precedent; unreviewed routine calls are useful for threshold checks only.

Replay sends the recorded caller turns through `/chat`, then applies the saved
decision through the dashboard route. Assistant turns are retained for provenance
but are regenerated by the application during replay. Replay never inserts a
human decision or booking directly. See [the integration guide](../../docs/ssa-008-precedents.md)
for the route contract, repeat-run behavior, and current blockers.
